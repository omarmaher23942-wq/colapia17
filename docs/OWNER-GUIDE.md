# دليل المالك الشامل لـ Colapia

> هذا الدليل لك أنت (المالك) ولفريقك: كيف تُطلق المنصة، وكيف تديرها يوماً بيوم، وأين تجد كل شيء. كل ما فيه يطابق الكود الحالي في `main`. للتفاصيل التقنية: `CLAUDE.md` (السجل الحي) و`docs/agency/PLAN.md` (الخطة والقرارات).

---

## 0) Colapia في صفحة واحدة

- **ما نبيعه:** فريق Colapia يبني لكل براند متجراً إلكترونياً مخصصاً ويستضيفه ويشغّله. التاجر لا يبني شيئاً بنفسه؛ يملأ استمارة قصيرة فقط.
- **الرحلة:** رسالة تواصل أو إعلان ← محادثة مع الوكيل الآلي (يُفصح أنه آلي) ← رابط الاستمارة `/start` ← صفحة «متابعة متجرك» ← فريقك يبني ويراجع ← التسليم ← **تجربة مجانية** (24 ساعة افتراضياً) ← دفع بتحويل (فودافون كاش/إنستاباي) تراجعه أنت ← المتجر مفعّل سنة ← تجديد سنوي.
- **بلا دفع:** يتوقف المتجر عند نهاية التجربة، ثم «تنبيه أخير»، ثم يُحذف (المدد تضبطها من «الأسعار والمدد»).
- **الأسعار الافتراضية:** الباقة 2,499 ج (متجر + سنة استضافة)، التجديد 1,299 ج/سنة، وعرض «الدائرة الذهبية» `GOLDEN599` بـ 599 ج لـ 5 براندات (استضافة مستمرة بلا تجديد مقابل فيديو إطلاق Collab). كلها تتغير من لوحتك.
- **بعد الدفع:** طلبا تعديل شهرياً للتاجر من لوحته (قابل للضبط)، وتعديلات فريقك بلا حد.
- **قواعد ثابتة في كل نص يراه العميل أو التاجر:** لا ادعاء أن الذكاء الاصطناعي يبني المتجر، ولا أسماء تقنيات بلا فائدة، ولا ميزة تُعلن قبل أن تعمل، ولغة تشمل الجميع (لا صيغ مذكر أو مؤنث حصرية، والأزرار مصادر: «إضافة للسلة»، «حفظ»). اختبار آلي في الكود يرفض الكلمات المخالفة.

## 1) الإطلاق: ما تفعله مرة واحدة

نفّذ بالترتيب، وكل خطوة يتحقق منها **مركز جاهزية الإطلاق** `/admin/launch` (يفحص كل خدمة حية ويقول لك السبب والحل بالعربية).

### 1.1 الكود وقاعدة البيانات
```bash
git pull origin main
npm install
npm run db:migrate
```
- يطبّق كل الـ migrations المعلقة حتى `0014_stock_alerts`. **لا تستخدم `db:push` على الإنتاج أبداً.**
- مركز الجاهزية يعرض «migrations معلقة» إن نسيت.

### 1.2 المفاتيح الأساسية (في Vercel أو Cloudflare)
| المفتاح | لماذا | بدونه |
|---|---|---|
| `DATABASE_URL` | قاعدة Neon | لا يعمل شيء |
| `UPSTASH_REDIS_REST_URL` / `_TOKEN` | الذاكرة المؤقتة وحدود المعدل | بطء وحدود معطلة |
| `AUTH_SECRET`, `MAGIC_LINK_SECRET`, `CRON_SECRET` | الجلسات والروابط الموقعة والمهام | الدخول والروابط تنكسر |
| `RESEND_API_KEY`, `EMAIL_FROM` | كل البريد (تسليم، دفع، تنبيهات) | لا بريد |
| `GOOGLE_CLIENT_ID` / `_SECRET` | دخول Google لك ولفريقك وللتجار | الدخول برمز البريد فقط |
| `GROQ_API_KEY` (+ اختياري `GEMINI_API_KEY`) | الوكيل الآلي والبحث بالصورة | الوكيل والبحث بالصورة لا يعملان |
| `VODAFONE_CASH_NUMBER`, `INSTAPAY_NUMBER` | ما يراه التاجر في صفحة الدفع | لا يعرف أين يحوّل |
| `OWNER_ALERT_EMAILS` | من يصله تنبيه كل إيصال دفع | الافتراضي بريدك |
| `QSTASH_*` | المهام المجدولة (التجربة، الإيقاف، الحذف، التذكيرات) | التجربة لا تنتهي وحدها |
| `META_*` | وكيل فيسبوك/إنستجرام | لا ردود آلية (الدليل: `docs/meta-agent.md`) |
| `R2_ACCOUNT_ID`، `R2_ACCESS_KEY_ID`، `R2_SECRET_ACCESS_KEY`، `R2_BUCKET` (+ اختياري `MEDIA_BASE_URL`) | صور المتاجر على Cloudflare R2 | تبقى الصور على UploadThing (`UPLOADTHING_TOKEN`) |
| `CF_API_TOKEN`, `CF_ZONE_ID` | النطاقات الخاصة للتجار تلقائياً | تُضاف يدوياً |
| `STORES_GITHUB_TOKEN`, `STORES_GITHUB_REPO` | «جهّز المتجر» يكتب فرع المتجر في GitHub | تنزيل ZIP بدلاً منه |
| `STORE_PREVIEW_KEY` | معاينة المتجر قبل تسليمه | المعاينة على نشرات Preview فقط |

القائمة الكاملة بأسماء المتغيرات في `.env.example` (قيم وهمية فقط).

### 1.3 الخدمات الخارجية
- **Resend:** وثّق نطاق colapia.com (resend.com/domains). إن ظهر في السجلات `domain is not verified` أعد التحقق.
- **Google OAuth:** أضف عنوان الرجوع `https://colapia.com/api/auth/callback/google`.
- **Meta:** اتبع `docs/meta-agent.md` (الاشتراك في `messages` و`message_echoes`).
- **Cloudflare (الاستضافة والصور والنطاقات):** اتبع `docs/deploy-cloudflare.md` خطوة بخطوة (الدفع 5$ شهرياً، نقل الدومين، R2، النشر، نقل الأسرار بأمر واحد، التحويل والرجوع بضغطة).

### 1.4 الإعدادات من لوحتك
1. `/admin/team`: أضف فريقك (بريد + دور). كل عضو يدخل بـ Google بنفس البريد.
2. `/admin/pricing`: السلّم، والتجديد، وكود الدائرة الذهبية ومقاعدها، ومدد التجربة والتنبيه والحذف.
3. `/admin/flags`: المفاتيح في القسم 5 أدناه.
4. `/admin/launch`: اضغط «اختبر البحث بالصورة» و«بريد تجربة» وتأكد أن كل الفحوص خضراء.
5. احذف متاجر التجربة القديمة قبل الإعلانات: `npx tsx scripts/ops/wipe-stores.ts` (معاينة) ثم بـ `--execute --confirm=DELETE-ALL-STORES`.

## 3) اليوم العادي: من أول رسالة حتى الدفع

### 3.1 جلب العملاء
- **قمع المبيعات** أعلى مركز القيادة `/admin` (7/30/90 يوماً): محادثات ← استمارات ← تسليم ← دفع، بنسبة كل خطوة، و«أضعف خطوة» مع نصيحة. وفيه تحويل التجربة لدفع ومقاعد الدائرة الذهبية.
- **التواصل مع البراندات: يدوي بالكامل** (أُلغي النظام الآلي نهائياً). رسائل جاهزة للنسخ بصيغ مختلفة، وقواعد 10–20 رسالة يومياً التي تحميك من الحظر، وردود الأسئلة الشائعة في `docs/OWNER-DM-MESSAGES.md`. بعد أن يرد الشخص يتولى الوكيل الحوار بجمل قصيرة، أو توقفه لتلك المحادثة وتكمل بنفسك.
- **المحادثات** `/admin/conversations`: كل محادثات الوكيل. ردّك من هنا أو من تطبيق إنستجرام لا يوقف الوكيل؛ الإيقاف لمحادثة بعينها بزر «أوقف المساعد هنا»، والإيقاف الشامل من `bot.enabled`. الوكيل لا يعرّف بنفسه ولا يقول إنه بوت إلا لمن يسأل صراحة «انت بوت ولا إنسان؟»، ويرد بجمل قصيرة بلا تكرار؛ وإن تعذّر الذكاء الاصطناعي (مفتاح منتهٍ) يصمت ويصلك تنبيه بريد مرة كل 30 دقيقة كحد أقصى. زر **«جرّب رداً كاملاً»** في `/admin/launch` يريك ما كان سيرد به.

### 3.2 الطلبات والإنتاج `/admin/requests`
1. يصلك بريد مع كل استمارة جديدة. افتح الطلب: كل بيانات العميل: منتجاته بكلامه وصورها، وطرق الدفع بأرقامها، والشحن والاستبدال، وملاحظته.
2. **أسند** منفّذاً ومراجعاً.
3. المنفّذ يحفظ **النطاق الفرعي** ثم «جهّز المتجر»: يُنشأ المتجر خلف بوابة «قيد التجهيز» بمسودة من الاستمارة، ومجلد `stores/<slug>/` في فرع GitHub (أو ZIP).
4. المنفّذ ينسخ **البرومبت** الجاهز ويعطيه لـ Claude Code داخل المستودع (المهارة `build-store`، والتعليمات في `stores/CLAUDE.md`)، ثم يكمل بنود الفحص ويرسل للمراجعة.
5. المراجع يكمل بنوده ويعتمد، أو يعيد بملاحظة.
6. أنت (أو المدير) تضغط **«سلّم للعميل»**: تبدأ التجربة، ويُثبَّت سعر المتجر الحالي، ويصل العميلَ بريد التسليم ورابط واتساب جاهز لك.
- العميل يتابع كل ذلك من صفحة «متابعة متجرك» (ملاحظاتك له تظهر هناك).
- **التأخر:** مهلة كل حالة من `production` في الإعدادات؛ يصلك بريد عند تجاوزها، و«بانتظار العميل» يوقف الحساب.

### 3.3 التجربة والدفع
- رسائل التجربة آلية (بأرقام المتجر الحقيقية فقط): أفكار في منتصف التجربة، تذكير قبل نهايتها، إيقاف عند نهايتها، تنبيه أخير، حذف.
- التاجر يحوّل ويرفع صورة الإيصال من «الباقة والاستضافة» في لوحته، فيصلك بريد فوري.
- **راجع في `/admin/payments`:** طابق المبلغ في محفظتك، ثم «تأكيد التحويل وتفعيل المتجر» (يصله بريد التفعيل وتبدأ سنة الاستضافة) أو «رفض» بسبب يراه.
- الدائرة الذهبية: الكود يُطبَّق في صفحة الدفع ويُعدّ مقعده؛ القبول يجعل الاستضافة مستمرة بلا تذكيرات تجديد.

### 3.4 بعد التفعيل
- **طلبات التعديل** `/admin/changes`: ما يطلبه التاجر (حصته الشهرية من `change_requests`) مع برومبت جاهز للتنفيذ.
- **التجديد:** تذكيرات آلية قبل 30 و7 أيام ويوم؛ بعد الانتهاء 14 يوم سماح ثم يتوقف المتجر عن الظهور **بلا حذف** حتى التجديد.
- **النطاق الخاص:** التاجر يربطه من لوحته؛ مع Cloudflare يتفعل وحده.
- **البيانات:** لا تسليم للكود؛ الاستضافة علينا دائماً. التاجر ينزّل طلباته وعملاءه CSV من لوحته، وأي نسخة أخرى من بياناته (المنتجات مثلاً) تُجهَّز له عند الطلب.
- **التقرير الشهري:** يصل كل تاجر مفعّل في أول الشهر بأرقامه.

## 4) الأسعار والعروض `/admin/pricing`
- **السلّم:** شرائح (أول 5 متاجر بسعر، ثم أعلى…) وسعر التجديد. السعر يُثبَّت لكل متجر لحظة تسليمه، فتغييره لا يمس من استلم.
- **الدائرة الذهبية:** الكود والسعر والمقاعد، والمستخدم منها حتى الآن.
- **المدد:** ساعات التجربة، والتنبيه الأخير، والحذف.

## 5) الإعدادات `/admin/flags`
| المفتاح | ما يتحكم فيه |
|---|---|
| `bot.enabled` / `bot.instagram` | تشغيل الوكيل كله / على إنستجرام (مفتاح طوارئ) |
| `intake` | إيقاف الاستمارة، السعة اليومية (تحدد موعد التسليم المعلن)، وحدود الحماية |
| `production` | مهلة كل حالة إنتاج بالساعات |
| `visual_search` | «البحث بالصورة» في كل المتاجر وحده الشهري لكل متجر (افتراضي 400) |
| `change_requests` | عدد طلبات التعديل الشهرية للتاجر (افتراضي 2) |
| `pricing` / `lifecycle` | تُعدَّل من صفحة الأسعار |
| `models` | تبديل نماذج الذكاء الاصطناعي بلا نشر جديد |

**تنبيه:** القوالب والبرومبتات التي تعدّلها من لوحتك (الرسائل، برومبت الوكيل) تتقدم على النسخ الافتراضية في الكود.

## 6) ما يملكه التاجر في لوحته (`colapia.com/dashboard`)
- **مهام اليوم:** أهم ما ينتظره مرتباً (طلبات للتأكيد، إيصالات، شحنات متأخرة، تقييمات، مخزون)، وطلب تقييم برسالة واتساب جاهزة، وما أُنجز اليوم.
- **جاهزية المتجر:** خطوات مقاسة من بياناته (الدفع، الشحن، السياسات، تجربة الشراء، الصور، دليل المقاسات…) مع «الخطوة التالية».
- **الطلبات:** قائمة ومراحل، تقدير مخاطرة لكل طلب استلام، رابط تأكيد للعميل، طلب عربون، فاتورة وطباعة، و**«طلب من الشات»** لتسجيل طلبات الرسائل (لصق رسالة العميل يملأ البيانات).
- **المنتجات:** مقاسات وألوان ومخزون لكل تركيبة، استيراد CSV، «نبّهني عند التوفر» ورسالة «رجع تاني» لكل منتظر، و**دليل المقاسات** بمساعد يقترح المقاس من الطول والوزن.
- **التسويق:** بكسل ميتا/تيك توك/جوجل، كتالوج المنتجات، روابط حملات بأدائها، وعُدّة إطلاق (صور ستوري وبوست ونصوص جاهزة).
- **العملاء، الخصومات، الشحن، السياسات، المحتوى، التحليلات، الفريق والصلاحيات، طلب تعديل، النطاق الخاص.**

## 7) ما يراه عميل المتجر
تصفح وبحث (وبحث بالصورة)، دليل المقاسات، سؤال عن المنتج على واتساب، سلة ودفع سريع (استلام/فودافون كاش/إنستاباي)، رسالة الطلب للمتجر على واتساب، «طلباتي» بحالة حية، رابط تأكيد الطلب، تقييم بعد الاستلام، و«نبّهني عند التوفر».

## 8) المهام المجدولة
| المسار | المعدل | ما يفعله |
|---|---|---|
| `/api/ops/sweep` | كل 10 دقائق | مهام دورة الحياة المستحقة والتنظيف |
| `/api/ops/tick` | يومياً | تنبيهات التأخر، فحص النطاقات، التقرير الشهري، حذف المسودات المنتهية |
| مهام QStash | في موعد كل مهمة | رسائل التجربة، الإيقاف، الحذف، تذكيرات التجديد |

على Cloudflare تعمل من `wrangler.jsonc` وحده؛ على Vercel Hobby استخدم جداول QStash. مركز الجاهزية يعرض آخر تشغيل لكل منها.

## 9) مشكلات شائعة وحلها
| ما تراه | السبب الغالب | الحل |
|---|---|---|
| لا بريد يصل | نطاق Resend غير موثّق | resend.com/domains ← أعد التحقق |
| «تعذّر البحث بالصورة الآن» | مفتاح Groq/Gemini أو نموذج متوقف | `/admin/launch` ← «اختبر البحث بالصورة» يعرض الخطأ الحقيقي، و«فك الإيقاف المؤقت» |
| التجربة لا تنتهي ولا تصل رسائلها | المهام المجدولة لا تعمل | `/admin/launch` ← المهام المجدولة، وراجع QStash أو cron Cloudflare |
| صفحة `/admin/requests` تطلب migration | لم تُطبَّق الـ migrations | `npm run db:migrate` |
| الوكيل لا يرد | `bot.enabled` مطفأ، أو اشتراك Meta ناقص | `/admin/flags` و`docs/meta-agent.md` |
| التاجر لا يستطيع الدخول | بريد مختلف عن بريد الاستمارة | يدخل بـ Google بنفس البريد أو «رمز على البريد» |
