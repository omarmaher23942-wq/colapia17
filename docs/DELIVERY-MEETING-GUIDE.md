# دليل ميتنج التسليم (للقراءة بصوت مسموع مع العميل)

> المدة المتوقعة: 60–75 دقيقة. الهدف: يخرج العميل بمتجر يعمل على حساباته، ويدخل لوحته، ويملك الكود. تكلّموا بالجمع وبلغة بسيطة، ولا تستعجلوا: كل نقرة يفعلها العميل بنفسه وأنتم تشاركون الشاشة.

## 0) قبل الميتنج (على الفريق، 20 دقيقة)
- [ ] تأكدوا من تأكيد الدفع في `/admin/payments` وأن الطلب في حالة «جاهز».
- [ ] ولّدوا المشروع من صفحة الطلب (زر تنزيل مشروع التسليم) أو `npx tsx scripts/store-template.ts --out <مجلد> --folder <slug> --check`، وتأكدوا أن `tsc` ينجح.
- [ ] افتحوا ملف `README.md` في المشروع وتأكدوا من اسم المتجر والبريد.
- [ ] جهّزوا رابط الميتنج، وأرسلوا للعميل مسبقاً: «جهزوا هاتفاً ولابتوباً وبريدكم، وبطاقة بنكية إن طلبت أي خدمة بيانات دفع (الخدمات المطلوبة مجانية في بدايتها)».
- [ ] جهّزوا حسابكم على GitHub (`{{OWNER_GITHUB}}`) لإضافته مشاركاً في مستودع العميل.
- [ ] افتحوا سجل التسليم في لوحة الإدارة لتسجلوا فيه رابط المستودع ورابط المتجر أثناء الميتنج.

## 1) الافتتاح (0–5 د)
«مبروك، متجركم جاهز. سنربطه الآن بحساباتكم أنتم، فيصير الكود والبيانات ملككم. سنُنشئ خمسة حسابات مجانية في بدايتها: GitHub وNeon وCloudflare وImageKit وGroq. لا نحتاج أي كلمة مرور منكم: أنتم تُنشئون وتنسخون المفاتيح وتلصقونها بأنفسكم.»

## 2) الحسابات (5–25 د)
لكل حساب: يستخدم العميل بريده نفسه المسجّل في الطلب.

### أ) GitHub (مكان الكود)
1. github.com ← Sign up (أو Sign in).
2. أعلى اليمين `+` ← **New repository**.
3. الاسم: `<اسم-المتجر>-store`، اختاروا **Private**، بلا README. ← Create repository.
4. **إضافة صاحب الوكالة مشاركاً:** المستودع ← Settings ← Collaborators ← **Add people** ← اكتبوا `{{OWNER_GITHUB}}` ← Add. (يتيح لفريقنا تنفيذ التعديلات لاحقاً؛ يمكنكم إزالته متى شئتم.)
5. سجّلوا رابط المستودع في سجل التسليم الآن.

### ب) Neon (قاعدة البيانات)
1. neon.tech ← Sign up بحساب Google أو البريد.
2. **Create project** ← الاسم نفسه ← المنطقة الأقرب (Frankfurt أو Singapore) ← Create.
3. في صفحة المشروع اضغطوا **Connect** ← اتركوا الخيارات الافتراضية ← **انسخوا رابط الاتصال كاملاً** (يبدأ بـ `postgresql://` وفيه `sslmode=require`). احفظوه في ملاحظة مؤقتة: هذا `DATABASE_URL`.

### ج) ImageKit (الصور)
1. imagekit.io ← Sign up ← اختاروا اسم Imagekit ID (مثل اسم المتجر).
2. القائمة ← **Developer options** ← API Keys. انسخوا **Private key** (Show ثم Copy) وانسخوا **URL endpoint** (يشبه `https://ik.imagekit.io/xxxx`).

### د) Groq (الميزات الذكية — اختياري لكنه موصى به)
1. console.groq.com ← Sign up.
2. **API Keys** ← Create API Key ← انسخوه فوراً (يبدأ بـ `gsk_` ولا يظهر ثانية).

### هـ) Cloudflare (الاستضافة)
1. dash.cloudflare.com ← Sign up ← تأكيد البريد.
2. القائمة ← **R2 Object Storage** ← (قد يطلب تفعيل R2 وبطاقة؛ الاستخدام الفعلي بحجم فيديو واحد مجاني تقريباً) ← **Create bucket** باسم `<المعرّف>-media` بالضبط (المعرّف مذكور في `wrangler.jsonc` ← `bucket_name`).

## 3) رفع الكود (25–35 د)
على لابتوب العميل (أو شاشتكم المشتركة):
1. فكّوا ضغط ملف المشروع (ZIP) في مجلد.
2. افتحوا Terminal داخل المجلد ونفّذوا بالترتيب:
```
git init
git add -A
git commit -m "init"
git branch -M main
git remote add origin <رابط-المستودع>
git push -u origin main
```
(إن لم يكن Git مثبتاً: ثبّتوه من git-scm.com، أو ارفعوا الملفات من واجهة GitHub بخيار **uploading an existing file**.)
3. تأكدوا أن الملفات ظهرت في GitHub، وأن `.env` غير موجود (لا مفاتيح في الكود أبداً).

## 4) ربط Cloudflare (35–50 د)
1. Cloudflare ← **Workers & Pages** ← **Create** ← **Import a repository** ← اربطوا GitHub واختاروا المستودع.
2. إعدادات البناء: Build command `npm run cf:build` · Deploy command `npx wrangler deploy` · Root directory فارغ.
3. **Variables and Secrets** (أضيفوها كما هي): `DATABASE_URL` · `IMAGEKIT_PRIVATE_KEY` · `IMAGEKIT_URL_ENDPOINT` · `GROQ_API_KEY` · `SETUP_CODE` (كلمة سرية قصيرة تقرؤها لهم الآن، تمنع غيرهم من فتح الإعداد قبلهم). `APP_URL` تُضاف بعد معرفة الرابط (الخطوة 6).
4. اضغطوا **Save and Deploy** وانتظروا اكتمال البناء (3–6 دقائق). إن فشل البناء فانسخوا أول سطر خطأ (راجعوا قسم الأخطاء أدناه).
5. افتحوا رابط `*.workers.dev` الظاهر. سيحوّلكم إلى صفحة الإعداد `/setup`.

## 5) الإعداد الأول `/setup` (50–60 د)
1. «الربط»: يجب أن تظهر القاعدة والصور «جاهز». ما هو «مطلوب» عالجوه من الخطوة 4 ثم «إعادة الفحص».
2. اضغطوا **تجهيز قاعدة البيانات** (يستغرق ثوان).
3. «حساب صاحب المتجر»: البريد ثابت. اختاروا كلمة مرور من 10 أحرف فأكثر (أدخلوا SETUP_CODE) ← **إنشاء الحساب**.
4. **احفظوا رمز الاسترجاع** (ينسخه الزر): يظهر مرة واحدة فقط. ضعوه في مدير كلمات المرور.
5. «متابعة إلى إعداد المتجر»: يكمل العميل الخطوات (الاسم والمنتجات والشكل والدفع والشحن والنشر) وأنتم بجانبه. جملة واحدة تقولونها: «كل ما تضبطونه هنا يمكن تغييره لاحقاً من اللوحة.»

## 6) النطاق (60–68 د)
- إن كان لديه نطاق: Cloudflare ← المشروع ← **Settings ← Domains & Routes ← Add** ← Custom domain. (إن كان النطاق عند مسجّل آخر فيُنقل أولاً خادم الأسماء إلى Cloudflare من تبويب Websites ← Add a site.)
- بعد التفعيل أضيفوا `APP_URL = https://نطاقه` (بلا / في الآخر) في Variables ثم أعيدوا النشر.
- سجّلوا **رابط المتجر** في سجل التسليم.

## 7) قائمة التحقق قبل الإغلاق
- [ ] الصفحة الرئيسية تفتح على الموبايل والكمبيوتر.
- [ ] تسجيل الدخول إلى `/dashboard` يعمل بكلمة المرور.
- [ ] لوحة التحكم ← الربط والمفاتيح: القاعدة والصور خضراء.
- [ ] رفع صورة منتج ينجح وتظهر في المتجر.
- [ ] (إن فُعّل) رفع فيديو الواجهة ينجح ولا يبطئ الصفحة.
- [ ] طلب تجريبي من المتجر يظهر في «الطلبات»؛ احذفوه أو أشيروا له تجريبياً.
- [ ] صفحة `/sitemap.xml` و`/robots.txt` تعملان.
- [ ] العميل حفظ: رابط المتجر، رابط المستودع، بريد الدخول، رمز الاسترجاع.

## 8) أخطاء شائعة وحلولها
| العرض | الحل |
|---|---|
| البناء يفشل `bucket not found` | أنشئوا حاوية `<المعرّف>-media` ثم أعيدوا النشر |
| `/setup` يقول القاعدة غير متصلة | `DATABASE_URL` ناقص أو مقصوص؛ انسخوه كاملاً ثم أعيدوا النشر |
| رفع الصور «غير مفعّل» | تحققوا من متغيري ImageKit وأعيدوا النشر، ثم «اختبار الاتصال» في الربط والمفاتيح |
| 404 على كل الصفحات | تأكدوا من نجاح `/setup` (وجود المتجر) |
| الروابط تظهر `localhost` | ضعوا `APP_URL` وأعيدوا النشر |
| نسي كلمة المرور | `/login/recover` برمز الاسترجاع |

## 9) طلب التعديلات بعد التسليم
اشرحوا: «في أسفل لوحة التحكم رابط **طلب تعديل**. تفتحون بوابتكم وتكتبون التعديل بالتفصيل وتُرفقون الملفات.» *(ملاحظة داخلية للفريق: لكل مشروع تعديل مجاني واحد خلال 7 أيام من التسليم، وما بعده 999 ج للتعديل؛ لا يُروَّج لذلك أثناء الميتنج ويُذكر عند السؤال فقط.)*

## 10) رسالة التسليم الجاهزة (تُرسل بعد الميتنج)
«مبارك! متجركم **{اسم المتجر}** يعمل الآن على: {رابط المتجر}.
لوحة التحكم: {رابط المتجر}/dashboard — البريد: {بريد الدخول}.
الكود في مستودعكم الخاص على GitHub: {رابط المستودع}. احتفظوا برمز الاسترجاع في مكان آمن.
لأي تعديل: من أسفل لوحة التحكم اضغطوا «طلب تعديل». شكراً لثقتكم.»

## 11) بعد الميتنج (على الفريق، 5 دقائق)
- [ ] سجّلوا في سجل التسليم (لوحة الإدارة): **رابط المستودع** و**رابط المتجر** وتاريخ التسليم.
- [ ] تأكدوا من ظهور `{{OWNER_GITHUB}}` مشاركاً في المستودع.
- [ ] انقلوا الطلب إلى «سُلِّم» ليبدأ عدّاد التعديل المجاني.
- [ ] دوّنوا أي مشكلة ظهرت وحلّها هنا لتحسين الدليل.
